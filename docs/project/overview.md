# 轻舟项目概览

轻舟是运行在用户本机的 Pi 编程助手，提供自由对话和按项目推进的需求工作区。密钥、会话、工作区与执行证据保存在用户机器，模型请求发送至用户选择的服务商。

## 核心业务

自由对话适合探索和临时任务，讨论片段可转为需求来源。工作模式使用“项目 → 需求 → 范围 / PRD 版本 → 执行轮次 → 交付 → 验收 → 集成”管理产品迭代，保持同一需求的连续对话。

需求先沟通并确认范围，再确认具体 PRD 版本。实施后仍可调整设计，PRD 与实现同步修订；最终人工验收时固化该 PRD，并更新关联模块的当前确认设计。新需求可引用固化 PRD，模块设计随各次子需求持续演进。

需求可以串行或并行，使用独立 Git 工作区。A 先完成但未合入时，B 可先合入；A 再基于最新主线准备候选、解决冲突并重新验证。实施完成、检查通过、人工验收和代码合入分别记录。

## 产品边界

- Agent 不自行确认需求、验收产品、固化 PRD 或合入主线。
- 只读讨论不修改代码，也不算已实施。
- 未确认设计不能开工，旧 PRD 的交付不能代替新 PRD 验收。
- 模块当前确认设计与对应代码的合入状态分别显示；提案不提前覆盖当前设计。
- 命令检查需真实执行且绑定代码与配置版本；完成声明、过程 Markdown 和 fake Pi 测试不等同于真实模型理解或人工验收。

## 文档层级

项目文档说明长期目标和约束；模块文档维护当前实现和演进来路；需求 PRD 保存每次变更的范围与方案。代码目录按已有 monorepo 组织，详细边界见 [架构](architecture.md)。
