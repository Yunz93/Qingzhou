# 文档审阅、Markdown 存储与项目历史精简

版本：v1。用户已在本对话授权按此版实施；实现与验证结果待用户验收。此说明不补造平台确认或验收记录。

## 1. 用户目标

- 审阅 PRD 与模块文档时，直接阅读有标题、列表、表格与代码块排版的正文。
- PRD 与模块设计以真实 Markdown 文件保存在项目内指定位置，支持项目级目录配置。
- 项目历史突出需求发生了什么变化，按需查看当时的设计、代码和对话。

本轮依据为用户在 2026-10-19 提出的改造要求。前一轮工作区中断恢复修复继续保留，不与本轮设计混合确认。

## 2. 已核实的现状

1. PRD 已固化正文、模块当前设计和模块历史使用 `pre` 展示 Markdown 源码。审阅者看到 `#`、表格分隔符和反引号，而非对应排版。
2. 保存 PRD 和创建模块主要追加应用状态；PRD 在实施时 materialize，模块文档随关联 PRD 实施才写入工作区。隔离项目新建示例模块后，界面显示仓库路径，但该路径没有实际文件。
3. `requirementFiles()` 和标准清单规定固定路径；没有用户可配置的 PRD、模块文档目录。
4. 一个已完成需求产生 34 条事件。项目历史同时呈现主线版本、比较器、全部事件和回放；点合入事件后默认展示大段完整 patch。
5. 现有合入会拒绝原项目目录的所有未提交改动。新增项目文档落盘必须一起处理平台自写文档带来的冲突。

截图与逐步观察见 [审查记录](../../../.qingzhou-test/review-audit/AUDIT.md)。

## 3. 审阅交互

### 3.1 阅读与编辑

- PRD、模块当前设计、模块提案和历史设计统一使用现有 Markdown 渲染能力。保留语义标题、列表、GFM 表格、链接、代码块和任务列表；不执行 Markdown 中的 HTML 或脚本。
- 默认进入“阅读”。未固化 PRD 提供“编辑”入口，编辑时保留源码文本区与独立预览，不在阅读视图常驻大文本框。
- 正文采用正常文档字号、行高与阅读宽度，避免整篇等宽字体和正文内部固定高度滚动。宽表格、代码块可以单独横向滚动，页面本身不溢出。
- 顶部只保留标题、状态、版本、实际文件路径及当前主要操作。代码基线、历史版本、系统 ID 和详细证据收进“版本与来源”。
- 未保存修改、外部修改冲突和当前文档保存失败直接显示；切换阅读、编辑、需求或页签不得丢失草稿或抢走正在输入的焦点。
- 保存和确认仍是两个动作。已固化版本默认只读；后续产品修改走关联子需求。

### 3.2 模块文档

- 左侧按名称检索模块，右侧默认展示与主线代码对应的模块设计；明确标注初始基线、主线版本或尚未合入的设计。
- “进行中的变更”和“历史版本”按需展开。选中提案后展示其所属需求、依据版本与渲染正文，不能把提案当成主线事实。
- 文档路径可以复制，桌面环境可打开项目文件；不把“导出 Markdown”作为主要持久化入口。

## 4. Markdown 文件与配置

### 4.1 文件契约

- 新建模块后即写入模块 Markdown；PRD 第一次显式保存时即写入项目 Markdown，不等待开始实施，也不要求用户下载导出。
- 可编辑正文以 Markdown 文件为唯一入口。应用状态保存 ID、路径绑定、正文 hash、版本、确认、交付和验收关联；旧 JSON 正文仅作为迁移与历史兼容来源，不能继续成为并行编辑入口。
- 保存成功必须意味着文件已原子落盘、版本记录已持久化；权限、目录冲突或磁盘错误时显示失败并保留编辑内容，不能假报成功。
- 历史正文也保存为 Markdown 版本文件；固化与交付仍引用准确版本及其 hash，已封存内容继续由 Git 对象和原交付校验。
- 外部编辑文件后，通过已有“同步文件修改”能力读回为新草稿/版本；不自动确认。界面与磁盘有不同修改时展示冲突，不能静默覆盖。
- 每个文档具有稳定路径绑定。改标题不自动改文件名；项目不同需求使用独立目录，模块提案保存在所属需求目录，保持并行隔离。

### 4.2 配置入口和默认值

- 项目设置增加“文档位置”，仅两个目录字段：PRD 目录、模块目录，并展示一个实际文件路径预览。
- 默认值分别是项目内 `docs/requirements` 和 `docs/modules`。PRD 使用 `<稳定需求目录>/PRD.md`，模块使用 `<稳定模块文件名>.md`；名称可读并附稳定 ID，重名不覆盖。
- 配置保存在现有 `docs/qingzhou/project.json` 的新增可选 `documentPaths.prds`、`documentPaths.modules` 字段。旧 v1 清单没有这两个字段时采用默认值，其他已有路径字段不改变。
- v1 支持项目相对目录；拒绝绝对路径、`..` 越界、`.git`、符号链接和两个目录相同/相互嵌套造成的歧义。无需新增环境变量、依赖或外部服务。
- 修改配置默认作用于新文档，已有文档继续使用界面展示的绑定路径。设置里明确说明这一点，不自动搬动已执行、固化或封存版本。
- 现有项目提供“导入已有文档”预览：列出旧 JSON/文件来源、目标路径、待写文件数和冲突。用户执行后写出真实 Markdown 并切换当前正文来源，保留旧数据。已有不同内容的目标文件必须先合并，不能覆盖。
- 执行、验证或集成正在使用的文档不能在此时迁移。旧历史与已封存交付始终保持原路径和读取能力。

### 4.3 与 Git 工作流衔接

- 新实施工作区从已确认版本复制文档快照；配置和路径绑定进入本轮依据，不能临时改用另一份正文。
- 项目文件写入不会自动提交、重置或丢弃用户改动。
- 合入预检不能简单忽略整个文档目录。只有平台登记、文件 hash 未被外部更改、且与当前候选相符的自写文档可以受控衔接；用户源码改动、人工暂存和未知文档仍阻止覆盖。
- 候选未涉及的其他需求文档保留；候选与本地文档有不同修改时先同步和合并，不能靠放宽脏目录保护通过。
- 文件保存、旧文档导入及受控 Git 衔接都保留持久化意图和恢复记录；中断后恢复到可明确重试的状态，不自行合入或重复用户确认。

本条替换 ADR-001 中“JSON 与 Markdown 均可编辑”的双入口设计；旧 JSON、已固化 PRD 和交付关联仍兼容读取。实现时同步更新 ADR 和目录规范。

## 5. 项目历史

- “演进与回放”改为“项目历史”。默认按需求聚合，每个需求一条摘要：名称、最近变更时间、当前阶段、最新交付或主线版本、检查结论。
- 展开后只呈现关键里程碑：确认设计、形成交付、验收、合入，以及需要关注的失败/中断。多轮执行和多次合入仍保留各自版本，不合并成虚假的一次成功。
- 点击里程碑打开“当时记录”，默认“变更说明”，另有“文件变化”和“当时对话”两个视图。设计正文渲染 Markdown，文件差异先列文件、选择后再展示该文件 patch。
- 完整事件、完整执行指令、工具 JSON、Git 细节收进“详细过程”。界面默认不显示 `#事件序号` 与长 UUID。
- 任意两个主线版本的比较放入独立“比较版本”入口，不常驻默认页面。“创建撤销需求”放入对应合入记录的更多操作，继续保留原行为。
- 项目级历史与需求内回放使用同一展示规则，避免两套术语和两套操作。
- 这次精简只改变展示与按需读取；不删除事件、历史对话、验证证据或撤销需求能力。历史检查标注“当时通过”，不冒充当前主线仍有效。

## 6. 实施顺序

### A. 阅读与历史交互

统一 Markdown 文档阅读组件，替换 PRD/模块/回放的纯文本展示；拆分阅读与编辑，收拢项目历史。保持现有存储与协议兼容，完成后应用即可独立使用。

### B. 项目 Markdown 存储

先更新 `packages/protocol` 并构建，再增加目录配置、项目文档读写与版本绑定、旧文档导入和 Git 衔接；最后接入界面。此阶段完成后，“保存文档”即能在项目目录看到文件。

预计涉及超过 8 个文件，集中在协议、设计与文件服务、审阅/历史组件及对应测试；不增加第三方依赖或独立后台服务。首要风险是文档落盘与 Git 原目录改动的衔接，必须用真实 Git 用例验证。

## 7. 代码入口

- 协议：`project-standard.ts`、`design.ts`、`client-commands.ts` 及导出。
- 服务：`workflow-design.ts`、`workflow-design-docs.ts`、`workflow-design-file.ts`、`workflow-module-docs.ts`、`project-standard.ts`、`workflow-service.ts`、`workspace-files.ts`。
- 界面：`RequirementDesign.tsx`、`ModuleDocuments.tsx`、`ProjectWorkflow.tsx`、`MainlineHistory.tsx`、项目设置及 `workflow.css`；复用现有 `react-markdown` 与 GFM 支持。
- 回归：项目标准、文档同步、工作流集成和 `project-workflow.spec.ts`；文档更新覆盖 ADR-001、模块基线与目录标准。

## 8. 验收

1. PRD/模块阅读区正确显示标题、列表、表格、链接和代码块；窄屏没有整页横向滚动，长文档不出现嵌套固定高度阅读框。
2. 编辑切换、页签切换、保存失败和外部文件冲突时，未保存内容保留；确认动作不因正文变化而被沿用。
3. 创建模块、保存 PRD 后无需实施即可在项目目录读到实际 `.md` 文件，界面与磁盘内容一致；重启仍可读取。
4. 自定义两个目录后，新文档写入预览路径；不合法路径、文件占用、写入失败和目录越界可恢复且无覆盖。
5. 旧项目可先预览再导入；旧历史 ID、确认、交付和只读回放不丢失；不改写已有固化记录。
6. 文档落盘后完整完成需求实施、检查、验收与合入；其他需求的草稿、用户源码及暂存内容不被覆盖。
7. 保存/导入/合入衔接中突然退出后，可恢复明确状态并重试，不自动执行确认或合入。
8. 仅一个已完成需求时，项目历史默认一条需求摘要，展开关键里程碑后可查看设计、单文件差异和当时对话；完整事件保留在详细过程。
9. lint、类型检查、单测、真实 Git 集成回归及相关浏览器流程通过，再复跑一个包含自定义目录和中断恢复的真实需求。

## 9. 边界与回退

本轮不改审批、验收、PRD 固化和 Git CAS 规则；不自动提交、推送或发版。回退时保留 Markdown 文件、导入前数据和路径绑定日志，历史兼容读取仍可用，不通过删除用户文档回退。
