# UI 与交互完成后设计提案

来源：轻舟 UI 重设计与交互精简 PRD v1。状态：已实施并自测，待用户确认；不替代已验收的模块基线。

## 对话与工作衔接

以同一视觉角色呈现首页、会话、输入和需求对话。创建时优先已选目录摘要，目录浏览按需展开；输入保持草稿和附件身份。模式采用明确单选，审批策略独立且沿用全部值与默认行为。回复中才展示追加/排队控件；会话动作保持鼠标、键盘和触摸可达。

转需求在无目标项目时可以进入既有新项目流程，完成或取消后回到原表单，不丢失范围与来源，不自动实施。来源证据和范围确认仍保留。

代码：`layouts/WorkbenchLayout.tsx`、`components/tasks/`、`components/composer/`、`components/board/ChatToRequirementDialog.tsx`、`WorkConversationDrawer.tsx`。验证复用前端交互和工作流 E2E，覆盖焦点、草稿和未授权执行保护。

## 项目工作编排

项目直接进入导航与需求列表，统计、分支和低频操作按需读取；保留五类项目视图、全部筛选、列表/看板与排序能力。每行显示一个关键状态；无需求时不显示无效批量选择和重复新建，单个需求隐藏批量选择及翻页。

需求保留连续对话和五个审阅页签、当前比例、交付选择和只读历史。上下文动作遵循原状态机；确认、封存、检查、验收、候选复审和最终合入分别进行。共享视觉角色不改变状态推导、证据时效及 Git 不变量。

代码：`BoardPage.tsx`、`ProjectWorkflow.tsx`、`RequirementWorkroom.tsx`、`WorkflowHistory.tsx`、`styles/workflow.css`。验证覆盖原工作流及空态筛选、旧深链、草稿恢复、准确版本审阅。

## 需求设计与模块文档

PRD 默认阅读，工具行紧凑，正文优先，当前可执行动作固定可达，无操作时不占底部空间。模块提案、路径和技术来源按需展开，未保存、冲突、缺少基线和过期证据直接显示。模块设计继续比较准确绑定版本，不能回退到最新设计冒充本轮基线。

代码：`RequirementDesign.tsx`、`RequirementModuleChanges.tsx`、`ModuleDocuments.tsx`、`DocumentReader.tsx`。验证覆盖跨页签草稿、保存失败、固化只读和准确模块基线。

## 执行与桌面表现

审批和提问复用统一表单与状态规范，所有风险、拒绝、等待和失败保留明确文字；不修改权限服务。Electron 保持当前壳、拖拽区域与最小尺寸；共享系统字体、双主题和辅助面板需在实际宿主验证。

代码：`styles/app.css`、现有审批/提问组件、`SettingsPage.tsx`、`apps/desktop/` 的当前运行配置。桌面配置与包体工作不属于本提案修改范围；验证时只使用隔离运行环境。
