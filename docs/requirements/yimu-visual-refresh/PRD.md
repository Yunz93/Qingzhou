# YiMu 风格的轻舟视觉改造

版本：v2。在 v1 视觉改造基础上，依据用户“对话内容的渲染需要优化，现在全堆在一起了”继续实施对话阅读改造；不替代平台确认、验收或固化记录。

## 目标与依据

以 `Yunz93/YiMu` 的 `21f7e9d9e80ddd0e6464849fed1cecdb61990776`、`docs/preview.png` 与 `dist/styles.css` 为视觉依据。轻舟代码基线为 `f448319`。保留现有对话、项目需求、设计、验收和历史业务，统一应用外壳、聊天、工作台、文档与设置的视觉语言。

## 设计

- 浅色采用纸白背景 `#f7f8f5`、浅鼠尾草侧栏 `#f0f2ec`、白色内容卡片、墨绿文字 `#29362e`、森林绿主色 `#426650`。辅助文字使用更深的灰绿，保证正文和控件对比度；警告、错误仍有独立语义色。
- 标题、品牌与空状态少量采用中文宋体风格，正文、表单和代码仍使用清晰的无衬线、等宽字体。使用本机字体回退，不新增远程字体请求。
- 降低毛玻璃和浮层阴影强度，采用细边框、适度圆角和更舒展的卡片内边距。聊天保持连续纸面，输入框有明确焦点；工作台保留高信息密度下的层次。
- 模式切换和当前会话有清晰的绿色选中态。品牌只在空间充足时显示，窄屏优先保留模式、当前对象和主要动作。
- 深色为同一风格的墨绿灰色阶；同步首屏背景、浏览器主题色和终端选择色，避免切换闪白或残留冷蓝面板。
- 适配 1440、1280、533、375 像素视口和触屏；不增加业务步骤、说明栏目或装饰性占位内容。

## 验收

1. 主要页面的背景、主色、边框、按钮、输入与文档阅读具有一致风格，明确借鉴 YiMu 而保留轻舟身份。
2. 浅色、深色的正文和关键控件有足够对比度；焦点、悬停、选中、禁用、失败和运行状态可辨认。
3. 桌面及手机无页面横向溢出；macOS 窗口按钮、标题和交互区不互相遮挡。
4. 对话发送、模式往返、需求页签、PRD 草稿、审阅差异、设置往返等现有行为回归通过。
5. 提供同一视口的改前与改后截图，记录实际命令、结果和验证边界。未执行真实模型或原生桌面验证时明确说明。

## 范围边界

不修改服务端、协议、权限、PRD 确认、验收和合入规则；不变更应用图标、版本号，不自动提交、推送或发版。模块变更提案见本需求的 `modules/`。

## v2：对话内容阅读

- 正文采用独立的阅读宽度、段落和标题间距，列表、引用、表格与代码块分别排版。用户提问、助手正文、思考记录和工具过程有明确层次，不给每段回复增加重复装饰标签。
- 生成中也渲染 Markdown，使用 React 延后更新优先处理输入；生成阶段不反复进行代码语法分析。组件身份保持稳定，避免图片与代码块随每个增量重新挂载。
- 代码块有独立标题和“复制代码”，复制原始代码；代码与宽表格在各自区域滚动，长路径不能撑宽页面。
- 连续只读操作与思考仍按需展开，执行过程使用更轻的视觉层级。运行中收到失败时自动展示具体失败输出，用户仍可收起。
- 保留复制回复、对话搜索、工具文件打开 / 撤回、滚动跟随与草稿行为，自由对话和需求内嵌对话共享同一渲染规则。
- 验证覆盖生成中的未闭合代码块、正常结束、代码复制、安全链接与 HTML、异步工具失败，以及浅深色和手机布局。
