# 项目标准与 Agent 规范

用户已授权：依据既有业务流设计项目标准文件结构、Agent 规范并改造轻舟。本文记录该次实现范围，详细结果待用户验收，不标为平台已固化 PRD。

## 目标与范围

将“沟通 → 确认范围 → 确认 PRD → 实施与设计迭代 → 回归 → 验收固化 → 后续子需求”转成项目文件结构与可执行规范。既改造轻舟自身，也让轻舟管理的项目和需求能够按标准建立文件。

不移动现有源码或历史 PRD，不更改发布流程，不补写既有 PRD 的确认或验收状态，不在原项目目录静默覆写文件。

## 方案

1. 根 AGENTS.md 作为入口，项目概览、架构、验证方式和阶段职责独立维护。
2. 模块当前设计关联源码、测试与各次子 PRD；需求拥有自己的 PRD、实施和验证记录。
3. 版本清单管理固定文档路径；项目初始化预览具体缺失项，补齐缺失文件并保留已有内容，不自动提交。
4. 新需求在独立工作区自动建立确认的设计 JSON、可编辑 Markdown 和只读上下文 / 模块基线。JSON 与 Markdown 按原版本合并，冲突先处理。
5. 轮次结束将设计调整读回为新 PRD，用户重新确认后实施；封存前和提交后检查设计与快照一致。
6. 规范强调阶段职责、持续有效的授权、准确版本交接、真实验证、人工验收与代码合入边界，默认同一 Agent 连续执行。

## 验收标准

- 轻舟文档导航可到达架构、模块、需求、模板和 Agent 规范，链接对应真实源码与回归入口。
- 初始化有预览、只新增、幂等且不覆盖已有 AGENTS.md；路径链接和无效清单明确报错。
- Agent 实施读取准确范围、PRD、模块基线及职责；不会因提示词笼统覆盖仓库规则。
- Markdown 设计变更读回为新 PRD；两种编辑入口冲突时不丢失任一版本，旧交付不能代替新 PRD 验收。
- 独立需求目录与快照可并行合入；文档未同步或系统快照被改写时不能封存为有效交付。
- 实施与验证记录不伪造用户验收、PRD 固化和代码合入事实。
