# 真实 DeepSeek 需求生命周期验证与修复

版本：v1。来源：2026-11-04 用户明确要求用一个具体需求、真实 DeepSeek API 完整走过生命周期，并修复过程中发现的功能、交互与审美问题。沿用既有 UI 精简方向及本任务构建、测试授权；最终效果待用户确认，不生成平台确认或验收事实。

## 最小范围

以独立样例“今天：极简待办工具”验证需求记录、真实只读讨论、设计提案、范围与 PRD 确认、真实实施、封存、真实测试、交付差异、逐项样例验收、候选复审、样例合入、历史与重开。样例支持添加、完成/恢复、筛选、删除、本地保存、存储失败反馈和 390px 布局，无框架或后端。

使用环境中已有的 DEEPSEEK_API_KEY，仅向官方 api.deepseek.com 发送模型请求；不复制凭据文件，不在文档、截图或日志打印密钥。使用真实 Pi 1.3.0 与 DeepSeek 接口返回的 deepseek-flash。主应用源码保持在当前工作区，样例的 Git 提交与合入只发生于独立样例项目。

## 修复契约

保留现有权限与关键确认，不通过自动放宽审批或伪造状态解阻。准确显示凭据来源；只读提示与真实可用工具一致；设计提案需完整协议校验、准确需求/范围/PRD 绑定，采用后仍为未确认草稿。兼容真实模型的合法结构化 JSON 时不能把普通示例 JSON 识别为提案，也不能选择多个候选中的一个。

界面继续采用暖白/金属灰、陶土强调、系统字体和最小元素集。修复以可复现的具体问题为单位；新的产品语义取舍另行确认，不扩展为新功能。

## 成功标准

1. 保存真实模型、会话、调用用量、执行记录、检查输出和 Git 结果，明确模拟测试与真实调用各自边界。
2. 实际浏览器操作完成样例主路径，重开恢复，并检查生成工具的正常、失败、键盘和窄屏行为。
3. 每项逻辑缺陷补可失败的回归；提案解析继续拒绝不合法及串需求数据，权限门槛不变。
4. 必要 lint、类型检查、单测、服务集成与相关 E2E 通过；截图支持审美和交互结论。
5. 实施与验证记录区分已修复、已验证、未覆盖及待用户确认；不提交或发布轻舟应用本身。
