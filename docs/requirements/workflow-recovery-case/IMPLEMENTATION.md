# 实施记录

## 本轮依据

用户要求端到端完成一个需求，定位并修复链路断点。运行前主线为 `4c1166a`；该次验证不提交或推送轻舟仓库；2026-10-20 用户另行授权随本轮文档改造交付。

## 已实现

- `WorkflowService.workspace()` 区分未完成创建的意图与已创建的工作区；仅在目标目录缺失且无创建完成事件时，由明确重试补完原创建操作。
- 重用原记录的 Git 基线与分支，保留 `git worktree add -b` 的分支占用保护。
- 已存在的目录仍校验真实仓库和分支；已完成工作区缺失时维持错误，不自动替换现场。
- 新增真实 Git 集成回归：创建失败后重启与重试、已完成工作区被外部移动、目标路径被无关文件占用。

## 同类路径检查

服务内共三处 `git worktree add`：需求工作区、集成候选、主线验证。后两者使用独立尝试目录；重启后的失败尝试支持重新验证或创建新尝试，不走永久复用缺失需求目录的路径。真实用例已验证集成检查中断后的重新验证。

## 边界

不改确认元数据、产品生命周期、协议或自动验收边界。隔离测试中的验收和合入用于验证入口与状态转换，不表示用户验收了轻舟本轮修复。已存在但异常的 Git 分支或工作区仍要求检查现场，不自动删除、重置或强制接管。
