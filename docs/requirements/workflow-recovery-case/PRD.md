# 工作流端到端与中断恢复

状态：按用户要求执行端到端用例并修复断点；实现与验证记录不代替最终人工确认。

## 目标与范围

用独立 Git 项目和独立应用数据完整推进一个真实需求：讨论、范围确认、PRD 提案与确认、实施、封存检查、验收固化、候选验证与复审、合入主线。检查实施与验证中突然退出后的恢复，不操作日常项目的需求或确认记录。

## 已复现的缺陷

`WorkflowService.workspace()` 在执行 `git worktree add` 前持久化工作区意图。若此时退出或创建失败，下一次明确重试把缺失目录当作已创建仓库读取，需求持续失败。

## 修复行为

- 重启只恢复中断状态，不自动启动执行或验证。
- 明确重试时，若工作区尚无创建完成事件且目标目录不存在，按原记录的分支与基线补完 Git 工作区创建。
- 已完成创建的工作区缺失、目录被占用、仓库身份或分支变化时保留现场，不覆盖已有文件，不重置 Git 分支。
- 重试仍按原确认的范围与 PRD 实施；设计同步与验收、固化、合入的既有约束继续生效。

## 验收与证据

1. 真实 Pi 在隔离项目完成一个有源码和测试的小需求，最终代码进入测试项目主线。
2. 实施中强制终止测试服务和其子进程后，修改、对话、确认记录保留；明确继续后完成交付。
3. 集成验证中强制退出后，旧运行标为中断，不能把它视为通过；重新验证和候选复审后才能合入。
4. 创建工作区的持久化与 Git 调用之间中断，重启不会自动重放，明确重试可以继续。
5. 已创建后被移动的工作区和占用目录中的无关文件保持不变。

突然退出使用测试实例的进程强制终止模拟，不宣称覆盖真实机器掉电、磁盘损坏或所有 Git 内部原子步骤。
