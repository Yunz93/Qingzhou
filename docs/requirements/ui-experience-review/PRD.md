# 全量 UI 与交互检视

版本：v1。依据用户本轮持续目标开展检视与修正；实现及验证结果待用户验收。

## 目标与范围

覆盖现有对话、输入与工具消息、会话侧栏、详情面板、工作台、需求工作区、文档阅读、项目历史、设置、向导及审批 / 提问弹窗。基于实际截图与交互修正信息层级不清、对齐与间距不协调、阅读困难、冗余说明和反馈不明确的问题。

沿用现有浅色 / 深色主题、图标、组件和导航。保持业务权限、确认、验收、固化及合入语义；不增设新业务流程，不提交、发布或更新用户安装的应用。

## 执行规则

1. 每个入口、主要状态和关键弹窗先获取当前截图，记录观察，再修正。
2. 主操作优先，技术依据与低频说明按需展开；阅读内容使用正常文档排版。
3. 保持草稿、焦点、返回位置、键盘导航与错误恢复；标签和辅助技术名称一致。
4. 检查桌面常用尺寸、最小 Electron 窗口和窄屏，兼顾浅色 / 深色，避免截断和整页横向溢出。
5. 逻辑修正补对应回归，完成 lint、类型检查、相关单元 / 集成 / 页面测试及 Electron 实际流程验证。

## 证据与验收

审查步骤、问题、修正与截图索引记录于 IMPLEMENTATION.md；真实命令、结果和限制记录于 VERIFICATION.md。截图保存于 .qingzhou-test/ui-audit/，不以旧截图或测试数量代替实际界面检查。

现有“文档审阅、Markdown 存储与项目历史精简”PRD v1 继续执行；本需求覆盖其周边和全产品的视觉与交互一致性，不缩减其验收项。
