# 轻舟产品化重构

版本：v1。状态：用户于 2026-11-08 回复“实施”，本轮已按此范围完成分批实施与自测，最终效果待用户确认。
来源：2026-11-08 用户要求使用 productize-app v0.6 重构轻舟；延续此前“最小必要功能、less is more”的产品方向。

## 用户与核心任务

面向通过本机 Pi 推进软件需求的个人开发者。主路径为：进入项目 → 建立或继续需求 → 讨论并确认范围和 PRD → 实施 → 审阅交付与真实检查 → 逐项验收 → 候选复审与合入 → 重开继续。自由对话保留为探索入口。

本轮重构围绕这条路径拆清职责、稳定草稿与异步行为，使后续修改不再同时牵动整页和服务编排。页面继续只显示当前任务所需信息，不新增面板或仪表盘。

## 当前依据与可复用资产

- 当前 checkout 为 f448319，叠加 mozi-ui-redesign 与 deepseek-lifecycle 的未提交修改。两轮修复与独立真实样例完整保留，不重置或提交这些内容。
- 既有 Electron + React/TypeScript + Node/Fastify + Pi RPC 与 pnpm monorepo 已覆盖本机能力；保留技术栈和数据格式。本轮不迁移 Tauri/Rust：当前没有证据说明换壳能改善核心闭环，反而会同时影响 Pi 子进程、PTY、IPC、安装与更新。
- 复用 protocol 的 Zod、requirement-state 投影、ReviewActions、既有弹窗/焦点机制、文档写入日志、Git/CAS 和测试夹具。
- ProjectWorkflow.tsx 当前同时定义项目订阅、项目设置/导航、需求列表、交付、验收、集成复审和检查详情；WorkflowService 同时承担编排和进程命令执行。按实际职责分离，不以文件行数为验收指标。

## 范围与分批交付

### 第一批：状态与草稿边界

把项目工作流订阅移到专用 hook，保留当前轮询和连接语义；请求使用项目身份与代次保护，旧项目的成功或失败不影响新项目。PRD 草稿从页面渲染中分离，集中校验缓存结构、版本及保存结果。未编辑草稿跟随新版本，本地修改保留且提示冲突；保存期间继续编辑不能被旧结果抹除；同一动作在事件入口防重复提交，失败可重试。

损坏的本地 PRD 草稿不造成工作区崩溃，也不被默认正文自动覆盖。显示一条就地恢复提示；用户可先下载原始恢复副本，再明确选择重新建立草稿。备份/下载未成功时不自动清理原值，不引入云端恢复或草稿历史管理。

### 第二批：界面按业务对象拆分

项目组件只负责项目导航、运行摘要和设置入口；需求列表、需求交付/验收容器、集成复审与检查详情成为有明确输入的组件。状态规则复用现有投影，避免复制。外观沿用当前主题、字体和最小元素集；五页签、独立动作区与跨页草稿保持。只在状态缺失、失败、重试或恢复确实需要时增加必要反馈。

主要涉及 ProjectWorkflow.tsx、RequirementDesign.tsx、RequirementWorkroom.tsx 及少量同目录组件、hooks/lib。小批移动后立即验证，避免一次改动全部页面。设置和完整对话布局只在这条路径确有依赖时调整，不另起视觉系统。

### 第三批：检查执行与编排分离

从 WorkflowService 提取检查命令执行的薄适配器，集中处理工作目录/环境、输出上限与脱敏、超时、中断、进程树清理。WorkflowService 继续拥有检查版本、调度名额、资源锁、事件与最终状态，保持原有时序和权限。不将状态机改成新框架，不重排 Git 或文档事务。

复用现有真实 Git/服务测试核对交付、检查失败、候选变更后失效、复审与合入保护。必要的行为修复先复现并补回归，再修改。

## 行为与视觉契约

1. 实施完成、检查通过、人工验收、PRD 固化和 Git 合入继续分别记录；界面不代替服务端制造事实。
2. 所有确认仍针对准确范围、PRD、交付、候选和配置版本；不放宽审批、路径或凭据保护。
3. 对象切换、保存中编辑、失败重试、断线重连和重开保留正确对象与用户输入。局部操作不锁死无关工作区。
4. 长内容按需展开；主操作明确，低频配置后置，错误说明影响和下一步。中文文案、IME、键盘、焦点和现有窄窗布局可用。
5. 缓存恢复失败不静默覆盖原始值。新增恢复提示是本轮唯一预定的产品行为补充，其余为保持行为的职责重构。

## 排除项

不增加账户、同步、数据库、插件系统、额外主题、后台服务或设置。无桌面壳迁移、旧数据批量迁移、发布/安装更新改造。无未经授权的提交、推送、打 tag、发版、替换安装版或用户项目合入。上轮样例历史与固化文档只读。

## 验收与验证

- PRD 缓存为 null、数组、缺字段或坏模块结构时仍可打开；原值保留，恢复决定明确。
- 可控延迟覆盖旧项目响应、保存中再编辑、同帧重复提交及第一次失败后重试；通过真实 UI 结果断言，不用文件包含字符串代替行为。
- 重构后正常项目 → PRD → 实施 → 交付/验收 → 候选复审/合入路径保持。模拟 Pi 用于可复现回归；已有真实 DeepSeek 样例仅回读验证历史，不把旧结果冒充本轮真实调用。
- 必要命令：pnpm lint、pnpm typecheck、pnpm test、相关服务集成、相关 E2E、pnpm build。每批只跑受影响检查；最后补必要总体检查，失败自行定位。安装新依赖和再次消耗真实 API 不属于本方案必需步骤。
- 浏览器实拍同一场景的修改前后、草稿恢复、操作失败与窄窗；桌面生命周期涉及处再验证实际 Electron。没有运行的环境明确列为未覆盖。

每批产物可独立检查；维护实施与验证记录，不以文档自行宣布用户验收或合入。完成后等用户确认。
