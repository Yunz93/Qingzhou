# ADR-002 代码对应的设计基线与集成复审

状态：已实施，待用户验收。来源：[工作流闭环补全](../requirements/workflow-completeness/PRD.md)。

## 背景

需求可以先验收、后合入，并允许乱序合入。以“最新验收模块文档”作为所有工作区的实施依据，会把尚不存在于该代码的设计当成现状；在集成候选中解决冲突，还可能改变已经验收的行为。

## 决定

- 新确认 PRD 绑定代码 commit 与该代码实际包含的模块设计版本，以 Git 祖先关系判定来源交付或集成是否包含。旧 PRD 保留原兼容校验。
- 同模块并行提案分别绑定自己的依据并可独立验收。合入通过组合检查和确切候选的人工行为复审，不在验收时提前强制覆盖另一需求。
- 固化 PRD 及需求执行快照在集成候选中保持原始内容。产品设计变化通过关联子需求重新确认。
- 仓库模块文档可在集成中合并，实际合入正文成为独立集成修订，通过 integrationId 关联目标主线、源交付和原 PRD；不改写源 PRD。
- 自动推进仅代办用户明确授权的实施、封存和有限修复；通过后等待人工验收，重启不自动重放。

## 影响

增加候选复审步骤；同模块并行冲突需要明确合并模块文档。系统保留已验收设计、主线对应设计与实施提案的区别。人工复审负责产品语义，检查通过不自动证明设计等价。
