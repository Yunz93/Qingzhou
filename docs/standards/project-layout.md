# 项目标准文件结构 v1

此标准沿用项目本来的源码目录，统一业务文档、Agent 入口、需求交接和可验证交付。

```text
AGENTS.md                         # Agent 入口：授权、阶段边界、仓库命令
README.md                         # 面向使用者与开发者的入口
apps/、packages/、tests/           # 轻舟现有源码；其他项目沿用自己的框架
docs/
  README.md                       # 文档导航
  project/                        # 长期产品目标、架构、验证方法
  agents/                         # 工作流与阶段职责
  modules/                        # 模块当前设计、代码与测试、来源 PRD
  requirements/<需求键>/          # 手工需求：PRD、实施与验证记录
  decisions/                      # 跨模块和兼容性决策
  templates/                      # 可复用文档模板
  prd/                            # 轻舟已有 PRD，保留历史链接
  qingzhou/
    project.json                  # 标准版本和固定文档路径
    requirements/<需求 ID>.json   # 兼容已有设计 JSON，保留依据版本
    requirements/<需求 ID>/
      AGENTS.md                   # 本需求文档的编辑规则
      CONTEXT.md                  # 系统生成的范围、PRD、模块和 Git 基线
      PRD.md                      # 可编辑的需求 PRD 正文
      modules/<模块 ID>.md        # 可编辑的完成后模块设计提案
      baselines/<模块>-<版本>.md   # 只读、确切版本的模块设计快照
      IMPLEMENTATION.md           # 实施计划、实际进展、设计调整和遗留项
      VERIFICATION.md             # 命令、人工观察、结果及未覆盖项
```

## 权责与唯一来源

| 信息 | 权威来源 | Agent 的行为 |
| --- | --- | --- |
| 用户授权和阶段边界 | 用户指令、根及相关路径的 AGENTS.md、平台阶段 | 已授权的范围继续推进；未确认的产品取舍提出问题 |
| 项目目标、架构、命令 | `docs/project/` 和实际源码 / 编排配置 | 修改相关实现时同步文档；不套用其他项目的包管理器 |
| 当前需求设计 | 平台 PRD 版本；工作区 JSON 与 Markdown 是编辑入口 | 改正文形成新 PRD，用户确认后实施，不改确认元数据 |
| 当前模块设计 | 已验收模块版本；仓库 `docs/modules/` 描述当前代码基线 | 提案与当前设计分别维护，标明设计和代码状态 |
| 模块变更依据 | PRD 关联的模块版本和 `baselines/` | 对照确切版本，不用新提案冒充既有设计 |
| 检查、验收、固化与合入 | 服务端执行证据、用户决定和 Git | 过程 Markdown 仅说明事实，不授予状态 |

同一需求在 JSON 和 Markdown 中只能有一致的有效设计。相对于 JSON 中 `prdId` 指向的原版本，若只有一处正文变化，读回该变化；两处改成相同内容则读回一次；两处改成不同内容则拒绝同步，要求先合并。模块关联 ID 与依据版本由 JSON / 平台管理，Markdown 编辑模块正文。以当前关联清单和 CONTEXT.md 为准，历史残留文件不自动成为生效提案；新增关联与旧 Markdown 不同且无共同依据时，先合并再同步。

系统在启动实施前将确认版本写入 JSON 与 Markdown，连同只读上下文纳入同一交付；轮次结束读回修改为未确认的新 PRD。封存前核对工作区，提交后再核对 Git 对象。旧的仅 JSON 工作区仍可读取，下一轮实施补齐新结构。

## 并行与文档更新

每个需求的文件使用稳定 ID，保存在自己的独立工作区，避免共享“当前需求”文件互相覆盖。模块基线按模块和版本命名；提案只写进本需求目录。验收时先检查全部模块的依据版本，再统一发布新设计；过期版本须合并并重新确认。

`docs/modules/` 在代码 / 设计基线变更时同步维护，明确来源与代码合入状态。平台的模块视图可即时查看当前确认设计、未合入交付和进行中的提案；工作区快照只说明其绑定版本，不宣称是全项目此刻的最新状态。系统不会在某个需求实施时覆盖原项目的模块当前文档。

## 初始化与兼容

“项目文件与规范”先列出具体缺失文件与内容预览，用户点击后只补齐缺失项。已有 `AGENTS.md`、项目文档和代码目录保留；不会自动提交。运行中的执行、检查和集成结束后才能初始化原目录。

新需求首次实施也会在其独立工作区补齐缺失标准文件，与本次改动共同审阅。初始化幂等；拒绝链接目录和符号链接文件；标准清单无效时保留文件并报告问题，不重写历史。

本仓库既有 PRD 保留在 `docs/prd/`，新增需求使用 `docs/requirements/`，通过索引关联。手工文档记录状态不冒充平台的确认、验收或固化历史。
